# LeftyChords v2.6 — Chord Lookup Enhancements

## Project Overview

Two requests for the Chord Name lookup tab: show more than 4 fingering
positions per chord (up to 8), and add a button-based root/quality picker
above the search input as an alternative to typing. This document records
what was actually built, since both features touch `data/guitar.json` in a
way that isn't obvious from reading the code alone.

## 1. Button-Based Chord Picker

Two button rows were added above the search input on the Chord Name tab
only (hidden on the Notes and Progressions tabs):

- **Root row**: the 12 chromatic root notes (`C` through `B`, sharps).
- **Quality row**: a curated set of 15 common qualities (Maj, Min, 7,
  Maj7, m7, Dim, Dim7, Aug, Sus2, Sus4, 6, m6, 9, m9, Add9). The full
  suffix vocabulary in the database is ~82 strings, many of them slash
  chords — too many to usefully show as buttons, so rarer/slash chords
  remain reachable only via the text search and autocomplete (unchanged).

Clicking a root or quality button fills the search input and runs the
search immediately, mirroring `App.searchByChordName`. Typing manually in
the search box clears the picker's active-button state, since the typed
query may no longer match the last button selection.

**Files:** `index.html` (markup), `css/styles.css` (`.chord-picker`,
`.picker-row`, `.picker-btn`), `js/app.js` (`buildChordPicker`,
`selectPickerRoot`, `selectPickerQuality`, `searchFromPicker`,
`updatePickerActiveStates`, `clearPickerSelection`).

## 2. Expanded Chord Positions (up to 8)

### Why this needed a data change, not just a UI change

`data/guitar.json` originates from `tombatossals/chords-db` (MIT). Diffing
our copy against the live upstream repo confirmed it's byte-identical —
there was no prior truncation to undo. The 4-position cap is inherent to
that dataset: 774 of 828 chord entries ship with exactly 4 stored
voicings. There's no way to show more without adding data from somewhere.

A brute-force fretboard search was tried first and rejected: it always
produced harmonically correct voicings, but some were not idiomatic
(e.g. fretting a note on the A-string that's available open, for no
musical benefit) — not what "conventional wisdom" chord shapes look like.

### What we did instead

`scripts/augment_chord_positions.py` merges in additional **published**
voicings from
[szaza/guitar-chords-db-json](https://github.com/szaza/guitar-chords-db-json)
(MIT licensed, a filtered fork of T-vK/chord-collection). For chords
where our suffix has a matching file in that dataset (most non-slash
qualities — major, minor, 7, maj7, m7, dim, dim7, aug, sus2, sus4, 6, 9,
m9, 11, 13, etc.), every one of their stored positions is decoded and run
through a harmonic validator before being merged in:

- **No foreign notes**: every played pitch class must be one of the
  chord's allowed tones (per `js/degrees.js` `CHORD_FORMULAS` /
  `INTERVAL_SEMITONES`, mirrored in the script).
  Reject otherwise (37 candidates were rejected this way across the
  whole dataset, all "13"/"maj13" voicings that include a natural 11th —
  a real jazz "avoid note" ambiguity that our own chord formulas
  deliberately exclude).
- **Essential tones must be present**: root, the 3rd/♭3 (or the sus
  degree if there's no 3rd), the 7th if the formula has one, any
  *altered* 5th (♭5/♯5 — since that's literally what defines
  dim/aug/altered chords), and the highest-numbered named extension
  (e.g. the 13 in a "13" chord). A plain perfect 5th and any
  lower/secondary extension tone may be omitted — that's standard
  practice in real guitar/jazz voicings (you can't always fit a 6-tone
  chord across 6 strings, so the 5th and lower color tones are what
  real players drop first).

Suffixes without a name match in the szaza dataset (slash chords, and a
handful of others like `add11`, `alt`, `madd9`, `9#11`) are left
untouched at their original stock position count — no synthesis
attempted for those, by design.

**Result:** 280 of 828 chords gained additional positions (1,094 added
total); 268 chords now show the full 8. The rest remain at whatever the
source data had (commonly 4).

### Re-running the script

```
python3 scripts/augment_chord_positions.py
```

Safe to re-run any time — it's idempotent (confirmed: re-running against
already-augmented data produces a byte-identical file and 0 new
positions added). Downloaded source files are cached in
`scripts/.szaza_cache/` (gitignored) so re-runs don't re-hit the network
unless that cache is cleared. If `js/degrees.js`'s `CHORD_FORMULAS` /
`INTERVAL_SEMITONES` ever change, update the mirrored copies at the top
of this script to match before re-running.

## 3. Position Ordering

All positions for a chord — whether original or added — are sorted into
a single list:

1. `baseFret` ascending (low frets / open position first, climbing the
   neck).
2. Tiebreak: most open strings first.
3. Tiebreak: most strings played first.

This matches the convention used by reference chord sites (Ultimate
Guitar, JustinGuitar, All Guitar Chords): open position first, then
ascending strictly by fret position, full chords before partial/muted
ones. There's no real "popularity" data available for guitar chord
voicings from any source we found, so fret-ascending + open-string
preference is the best available proxy for "easiest/most commonly
taught first."

## Bug Fixes

- **Add9 picker button stretching full-width**: `.picker-btn` used
  `flex: 1 0 auto`, which let a lone button that wrapped onto its own row
  stretch to fill it. Changed to `flex: 0 0 auto`.
- **"Open" label shown for non-open positions**: the chord card label
  showed "Open" for any position with `baseFret === 1`, but some added
  positions are fretted at baseFret 1 with no open strings at all (e.g.
  `[-1,3,2,4,1,-1]`). Now only labeled "Open" when the position actually
  contains an open string (`frets.includes(0)`).

## Notes

- Original chord database: tombatossals/chords-db (MIT license).
- Additional voicings sourced from szaza/guitar-chords-db-json (MIT
  license), itself a filtered fork of T-vK/chord-collection.
- `data/guitar.json` is now a **derived** file, not a raw upstream copy.
  Don't re-pull a fresh copy from tombatossals/chords-db to "update" it —
  that would silently discard all the augmentation work above. Re-run
  `scripts/augment_chord_positions.py` instead if the upstream chord
  catalogue ever needs refreshing.
